# Harness Backlog Policy

## When To Add A Proposal

Only add a backlog proposal when a run reveals a reusable Harness improvement.

The proposal must include at least one of:

- proposed guide change
- proposed sensor/script/test change

## Avoid Vague Proposals

Do not add vague proposals such as:

- improve code quality
- make agent better
- add more tests

Prefer concrete proposals such as:

- thêm validation rule cho required form fields
- thêm smoke test cho empty form submission
- thêm architecture rule chặn business logic trong controller
- thêm evaluator rule yêu cầu Playwright evidence cho UI persistence

## Language

Backlog proposals must be written in Vietnamese.

Technical examples may keep English commands, filenames, schema keys, API fields, or code snippets.
